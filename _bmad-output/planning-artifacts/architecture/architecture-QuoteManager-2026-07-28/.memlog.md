- (decision) The queue carries integration events for effects OUTSIDE the consistency boundary only - notification dispatch and future external system sync. Invariant maintenance and audit are transactional and never queued.
- (decision) Audit is a transactional projection of domain events written in the same transaction as the state change, not a logging concern. - (decision) Transactional outbox is the sole publish path. A SaveChanges interceptor writes domain events to an Outbox table in the same transaction; a single dispatcher BackgroundService drains it. Delivery is at-least-once so every consumer must be idempotent on the outbox message id.

- (event) Schema review with the candidate surfaced a real defect: only one foreign key existed (Quotes to Requests). - (decision) Surrogate key type is orthogonal to normal form - clarified explicitly because the two questions were tangled. UUIDv7 retained over INT IDENTITY for one concrete architectural reason: aggregates raise domain events before SaveChanges, and the audit and outbox rows written by the interceptor carry the subject id. A database-generated int is not available until after the INSERT, so those rows would reference 0 unless the save is split into two round trips, which would also stop the audit write being atomic with the change it describes. Secondary benefit: ids are not enumerable in URLs.
- (decision) QuoteStatus lookup table added, keyed by the status NAME rather than a surrogate int. An int key would force Quotes.Status to become an ordinal, and the AD-3 filtered index compares against the literal Accepted - so the index and the enum would need hand-alignment, which is the exact silent drift that index was already hardened against. Keying by name gives referential integrity, keeps the index working untouched, and leaves the database readable.
- (constraint) EF matches foreign keys on CLR type, not store type. A string-keyed lookup would not bind to the quote enum column even though both persist as identical TEXT. - (decision) RequestInvitations added as the genuine many-to-many the candidate was reaching for: composite primary key on (RequestId, VendorOrganizationId), so the database itself rejects a duplicate invitation. - (event) A real, pre-existing correctness bug was found and ruled out during this work, and a real test-harness bug was found and fixed. The suspect: DemoDataSeeder appeared to leave an untouched Submitted quote (hvacKestrel) persisted as UnderReview. Bisection - a pure in-memory domain repro, then a direct-seeder-with-SQL-logging repro - proved the domain and persistence layers both write and read this correctly in isolation.
